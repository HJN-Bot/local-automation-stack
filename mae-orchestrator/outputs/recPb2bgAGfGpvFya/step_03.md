**1. 与 Claude API 的集成：基于工具调用的闭环编排**
*   **架构类型：** 闭环 / 多轮 Agent (Closed-Loop / Multi-Turn Orchestration)。
*   **交互机制：** 深度利用 Claude API 的 Tool Use（函数调用）能力。系统不再将 LLM 仅视为文本生成器，而是将其定义为能够操作外部工具的决策核心。API 调用中预设了特定的工具 schema（如 `read_file`, `write_to_file`, `run_command`），允许模型自主选择工具。
*   **动态决策：** 不同于 Codex CLI 的单一输出，Claude Code 在单次交互中可能进行多次 API 轮次。模型首先分析请求，决定调用搜索工具读取代码，待获得结果后，再决定调用编辑工具修改代码。这种编排方式实现了任务分解与执行的自动化。

**2. 上下文处理：主动检索与智能窗口管理**
*   **主动上下文感知：** Agent 具备主动探索项目结构的能力。面对模糊指令（如“修复登录 bug”），它会自主调用搜索工具（如 `ripgrep` 或语义搜索）来定位相关文件，而非依赖用户手动粘贴代码。
*   **长上下文策略：** 针对大型项目，架构通常包含上下文管理策略。它通过“摘要”或“滚动窗口”机制，在保留关键文件内容和对话历史的同时，淘汰过时的中间步骤，以适应 API 的 Token 限制。
*   **会话持久性：** 它在内存中维护项目的“心智模型”。它知道当前的工作目录、已读取的文件列表以及之前的操作结果，使得后续指令可以基于先前的上下文（例如“在此基础上增加错误处理”）。

**3. 文件操作工作流：直接交互与自我修正循环**
*   **直接文件系统访问：** Agent 拥有通过工具直接读写文件的权限。它不再生成 `sed` 或 `awk` 等 shell 命令字符串让用户执行，而是直接生成文件内容的新状态或 Diff 补丁，由工具层完成文件写入。
*   **执行与反馈回路：**
    1.  **规划：** LLM 生成编辑计划。
    2.  **执行：** 工具层修改文件。
    3.  **验证：** Agent 可以自动运行测试、Linter 或编译命令来验证修改。
    4.  **修正：** 如果验证失败（报错），Agent 会自动读取错误信息，分析原因，并生成修复代码，进入下一个循环。
*   **安全性机制：** 尽管是自动执行，系统通常在执行破坏性操作（如 `git force push` 或删除文件）前引入审批机制，而在读取、搜索和代码修改层面保持高度的自动化。
