### 1. 现有视频生产相关Skill/工具/脚本梳理

**需确认workspace中的实际资产**（假设基于常见视频生产流程推测）：
- **基础工具链**：
  - **脚本生成**：可能依赖Claude Code生成分镜脚本/文案（如`script_generator`）
  - **TTS引擎**：如`edge-tts`或`azure-tts`等Skill
  - **字幕工具**：`srt_generator`（时间轴对齐）、`subtitle_embedder`（硬字幕压制）
  - **视频合成**：`ffmpeg_wrapper`（剪辑/转码）、`video_compositor`（画中画/特效）
  - **素材处理**：`image_resizer`、`bgm_processor`等

- **潜在实验性Skill**：
  - 动态分镜（`storyboard_planner`）
  - AI画外音（`voice_cloning`，可能尚未接入）
  - 自动化剪辑逻辑（`auto_editor`）

**关键问题**：需明确哪些是已通过Claude Code验证的临时脚本，哪些是标准化Skill。

### 2. 当前链路可跑通步骤验证

**假设当前实际状态**：
- **✅ 可跑通**：
  - **脚本→TTS→字幕**：通过Claude Code调用`script_generator`+`edge-tts`+`srt_generator`生成带字幕的音频
  - **基础合成**：静态图片+字幕音频合成简易视频（`ffmpeg_wrapper`基础功能）
  
- **⛔ 阻塞点**：
  - **复杂剪辑**：多轨道合成、动态转场依赖手动调整
  - **质量校验**：缺乏自动化成片质量检测（如字幕同步率、音频清晰度）
  - **输入依赖**：内容采集流水线的原始素材未标准化（如无统一命名规则）

**验证方法**：对现有Claude Code任务流进行端到端沙箱测试，记录各环节成功/失败率。

### 3. 与内容采集流水线的输入接口关系

**可能的依赖项**：
- **结构化输入**：
  - 采集流水线需提供`素材包`（视频片段/图片/BGM）及元数据（如`scene_tags.json`）
  - 元数据需包含：分辨率、版权状态、推荐使用场景（如"开场片段"）
  
- **未解决问题**：
  - 采集素材与脚本的匹配度（如脚本要求"城市夜景"但采集库中无对应标签）
  - 版本冲突：采集流水线更新素材版本时，视频生产如何同步更新引用

**建议接口规范**：
```python
class MediaInput:
    assets: List[{
        uri: str,  # 素材路径
        type: Enum["video", "image", "audio"],
        duration: float,  # 视频/音频长度
        tags: List[str]  # 至少包含采集时的AI打标结果
    }]
    script_requirements: Dict  # 脚本要求的素材特征（如"需要2个过渡片段"）
```

### 4. 收敛建议与最小可交付路径（MVP）

**收敛原则**：
- **冻结功能**：暂停所有非核心Skill开发（如动态分镜生成）
- **标准化输入**：强制要求内容采集流水线输出带标签的素材包
- **主干流程MVP**：
  ```mermaid
  graph LR
    A[采集素材包+脚本] --> B{素材匹配检查}
    B -->|通过| C[生成TTS+字幕]
    C --> D[单轨道视频合成]
    D --> E[基础质检]
    E --> F[输出成片]
  ```

**关键动作**：
1. **Skill整合**：
   - 将Claude Code中的临时逻辑迁移到`video_pipeline_controller` Skill
   - 废弃实验性分支（如单独的字幕压制的Python脚本）

2. **容错设计**：
   - 在素材匹配失败时自动触发`claude_fallback`生成替代文案
   - 合成阶段强制分辨率统一（如自动裁剪到1080p）

3. **度量指标**：
   - 定义"成片率"（成功输出视频/总任务数）
   - 监控平均处理时长（从输入到成片）

**风险控制**：
- 优先保证80%的简单视频（如图文解说类）可全自动生成
- 剩余20%复杂案例走`human-in-the-loop`模式（标记后转人工）
