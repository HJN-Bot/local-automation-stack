### **2. Title命名规范现状**
- **当前实践**：
  - 数据源级别：`[平台]_[数据类型]_[日期]`（如 `Twitter_Trends_20230915`）
  - 文件级别：混合使用`camelCase`和`snake_case`，缺乏强制校验。
  - 问题：
    - 跨团队协作时存在歧义（如「微博」用`Weibo`或`SinaWeibo`？）
    - 版本控制未体现在命名中（如`v1`/`latest`后缀缺失）。

- **建议**：  
  参考`Google Style Guide`制定强制规范，例如：  
  `[ProjectPrefix]_[DataSource]_[ContentType]_[YYYYMMDD]_[Version]`  
  （例：`AIRadar_YouTube_Video_20230915_v2`）

---

### **3. 与视频生产流水线的协同边界**
- **明确边界**：  
  - **采集输出**：提供标准化元数据（标题、标签、原始URL）及原始素材（视频/图文）。  
  - **视频生产输入**：接收编辑指令（如「5分钟剪辑版」）并返回成品ID。  
  - **争议点**：  
    - 视频AI预处理（如字幕生成）应由采集链还是生产链负责？  
    - 是否需要共享中间状态数据库？

- **技术接口建议**：  
  通过消息队列（如AWS SQS）传递JSON Schema化任务，例如：  
  ```json
  {
    "task_type": "video_clip",
    "source_id": "采集流水线ID",
    "output_params": {"duration": "300s", "format": "mp4"}
  }
  ```
